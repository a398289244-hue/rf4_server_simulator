# RF4 Go 后端交付说明书

版本：`0.1.0`
整理日期：`2026-11-03`
客户端：`4.0.25034`
运行环境：Windows x64 + Go 1.27.3+ + MySQL 8.0+

## 1. 交付定位

本次交付的是 RF4 本地后端的 Go 单进程版本，目标是把登录、进场、玩家数据、背包、鱼护、技能、商城、装配、钓饵和钓鱼主链路跑通，并确保运行期状态来自于真实 MySQL。

不包含：

- 管理后台与管理员鉴权
- 玩家管理、封禁、禁言、邀请、CDK、邮件等运营系统
- 真实玩家数据库导出
- 游戏客户端本体
- 抓包回放作为运行数据

运行时代码不读取 `replay_bootstrap.json`、`s2c_uuid` 或剧本帧；这些只允许作为测试参考答案或离线分析材料。

## 2. 本次完成的功能

### 2.1 登录与连接

- HTTP 登录网关支持 `login.php` 与 `login_token.php`。
- 同时监听 `19214` 和客户端内置的 `7515` 兼容入口。
- 登录票写入 MySQL `login_tokens`，重启后仍可续期。
- TCP 完成首包、token 认证、Hermes 握手、RC4、ACK、心跳与断线诊断。
- 未实现 RPC 返回明确的错误回执，避免客户端等待超时。

### 2.2 玩家进场与基础状态

- 玩家进场、个人档案、状态推送和等级经验。
- 地图、天气、9 个游戏配置块。
- 服务器信息、时间、水域定义、竞赛空回执、区域和频道信息。
- 个人档案和状态数据优先读取 MySQL，不使用旧玩家快照。

### 2.3 玩家数据

主要 MySQL 表：

| 表 | 用途 |
|---|---|
| `users` | 账号、昵称、等级、钱包、经验 |
| `login_tokens` | 登录票与续期 |
| `objects` | 背包、装备和制作产物 |
| `keepnets` | 鱼护记录 |
| `fish_records` | 渔获流水 |
| `skill` / `skill_node` / `skill_points` | 熟练度、已学节点、技能点 |
| `containers` / `container_items` | 容器 |
| `shortcuts` | 快捷栏 |
| `rig` / `rig_component` | 装配镜像 |
| `static_item_def` / `static_item_catalog` | 物品静态定义 |
| `static_shop_item` | 商城货架 |
| `purchases` | 购买流水 |
| `static_recipe` | 鱼饵配方 |
| `static_species_weight` / `static_map_fish_roster` | 鱼种与地区名册 |

完整建表脚本见 `docs/mysql_schema.sql`。

### 2.4 背包、容器与鱼护

- `4/1`、`4/4`、`4/5` 按容器号区分背包、鱼护和其他容器。
- `4/5` 的 GUID 按“客户端点名下载”处理，修复重登后购买装备消失。
- 鱼护从 `keepnets` 实时读取，容量真实返回 `N/100/150`。
- 空鱼护显示 `0/100`，不再出现空列表却显示 `17/0` 的旧缓存数字。
- 新鱼优先复用保存的鱼卡字节，旧鱼按种类、重量、长度、GUID 和时间重建。

### 2.5 技能

- 技能树、学习节点、重置单节点、全部重置。
- 技能熟练度和已学节点均以 MySQL 为准。
- 捕获鱼饵熟练度成长已接入，上限 `100%`。
- 技能变化会同步到技能表并随登录恢复。

### 2.6 商城与购买

- `22/1` 商城货架现拼。
- `22/2` 购买支持金币/银币价格、库存、钱包扣款、物件生成和购买流水。
- 可堆叠数量物品优先合并到已有堆。
- 可展开的组合包会拆成真实物件。
- 缺少物品定义或无法生成客户端物件时，货架会拦截异常条目，避免出现空框商品。

### 2.7 装配、容器和快捷栏

- 装配、单件拆卸、全部拆卸。
- 鱼线、渔轮和钓组零件同步写入 `objects.elem`、`rig`、`rig_component`。
- 快捷栏绑定、改绑和取消绑定均持久化到 MySQL。

### 2.8 挖饵

- 支持铲子 `tool_shovel` 和红虫长柄勺 `tool_scoop`。
- 捕获鱼饵熟练度分 `0/20/40/60/80` 五个阶段，阶段越高可挖到的饵种类越多。
- 每次未满 `100%` 时增加 `0.1%` 熟练度。
- 产物写成标准物品记录并进入 MySQL 背包，已有的可堆叠鱼饵会累加数量。

### 2.9 鱼饵制作

- 通过 `9/1` 解析 MySQL `static_recipe` 配方。
- 每次制作固定产出 `30` 个，多次制作按次数累加。
- 产物写入 `objects`，优先堆叠到已有记录。
- 每次有效制作增加 `0.1%` 捕获鱼饵熟练度，达到 `100%` 后不再增加。

### 2.10 钓鱼

- 抛竿准备、抛出、咬钩推送、起鱼结算和留鱼。
- 鱼护写入 `keepnets`，渔获写入 `fish_records`。
- 鱼种按客户端当前进入的 `level_*` 地区，从 `static_map_fish_roster` 随机。
- 没有当前地区名册时不会跨地区乱出鱼。
- 支持体重、长度、鱼卡和搏斗基础帧构造。

## 3. 启动与日志

### 3.1 命令行启动

```powershell
.\build.ps1
.\start-server.ps1
```

默认端口：

- `19213`：游戏 TCP
- `19214`：HTTP 网关
- `7515`：CN 客户端兼容 HTTP

同一时间只能运行一个占用这些端口的后端实例。

### 3.2 IDEA 启动

运行入口：`cmd/rf4server/main.go`

工作目录：`rf4_server_go`

环境变量：

```text
RF4_DATA_DIR=<项目绝对路径>\data
```

程序参数示例：

```text
--http-port 19214 --http-compat-port 7515 --tcp-port 19213
--mysql-host 127.0.0.1 --mysql-port 3306
--mysql-user rf4 --mysql-pass rf4pass --mysql-db rf4
--logs logs
```

IDEA 控制台会实时输出日志，日志文件写入 `rf4_server_go/logs/`。

### 3.3 数据库准备

1. 创建 MySQL 数据库 `rf4`。
2. 导入 `docs/mysql_schema.sql`。
3. 导入项目需要的静态物品、商城、鱼种、水域和配方基础数据。
4. 修改 `data/db.json` 中的示例账号，或直接按当前网关格式配置开发账号。

示例账号仅供联调：`return2` / `rf4demo`。

## 4. 测试与验收

本版已执行：

```powershell
go test ./...
go vet ./...
go build ./...
```

结果全部通过。

建议朋友接手后先验证：

1. 启动后 IDEA 控制台显示 MySQL、协议表、技能定义和配置块载入成功。
2. 客户端能登录并进入游戏。
3. 重登后背包物品数量和鱼护数量不丢失。
4. 商城可购买，商品有名字、模型和详情。
5. 铲子/长勺可挖到鱼饵并在背包累加数量。
6. 制作鱼饵一次增加 30 个，并增加 `0.1%` 捕获鱼饵熟练度。
7. 当前地图抛竿后只出该地区名册内的鱼。

历史迁移对账测试默认关闭。需要人工核对旧数据迁移时：

```powershell
$env:RF4_LIVE_SNAPSHOT_AUDIT = '1'
go test ./internal/gamestore
```

该开关只用于历史审计，不是运行时数据来源。

## 6. 目录与交付边界

```text
rf4_server_go/
  cmd/rf4server/             主后端
  internal/                  业务模块
  data/                      脱敏示例账号、静态定义和测试样本
  docs/mysql_schema.sql      实际运行时数据库结构
  README.md                 快速说明
  交付说明书.md              本文件
  build.ps1                  测试、检查、构建
  start-server.ps1           启动与 MySQL 参数
  VERSION.txt                版本信息
```

交付包不包含：

- `.idea/`
- `logs/`
- `bin/` 中的构建产物（发布压缩包单独放入可执行文件）
- `dist/` 历史包
- `projectFilesBackup*/`
- 真实玩家机器码、IP、管理员数据和 MySQL 业务库导出

## 7. 协作约定

1. 先读 `README.md` 和本说明书。
2. 改动协议前先跑相关包的测试。
3. 业务代码只允许通过 `internal/gamestore` 访问数据库。
4. 运行时禁止读取录制或抓包快照。
5. 修改数据库字段时同步更新 schema、`gamestore` 和测试。
6. 每次实机修复记录：客户端现象、日志证据、根因、修复点和回归测试。
