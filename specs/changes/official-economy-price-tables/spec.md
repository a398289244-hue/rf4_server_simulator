# 商城与鱼市价格数据表

Status: done

## Problem Statement

商城多数货架依赖同品牌/同类型模板及估价，鱼市则使用一张单地图玩家样本表再乘地图倍率。两处价格的来源和精度无法逐条追溯，后续拿到官服数据时也不能只替换对应条目。

## Solution

为商城和鱼市建立带来源字段的价格定义表。商城按店铺和物品取价；鱼市按地图、鱼种、档位和重量区间取每公斤价格。运行时优先使用定义表，未采集的条目保持当前回退路径，官服抓包记录可单条覆盖而不改变其他商品或鱼种。

## User Stories

1. 作为运营者，我可以为一个商店商品或一类鱼的一个重量区间录入带来源的价格，客户端询价和结算使用同一条记录。
2. 边界：尚未录入的数据继续使用现有静态目录或鱼市回退价，不能变成零价、不能影响已录入官服记录。

## Implementation Decisions

- 在 `internal/store` 增加迁移、价格仓储和只读查询；玩家库保存价格定义，静态库不写入。
- 商城当前静态 `shop_item` 在迁移时复制到商城价格定义表，并标识为本地静态快照；以后官服记录以同一店铺和物品键覆盖。
- 鱼市把现有阿赫图巴河 251 鱼种四档价格迁入鱼市价格定义表，标识为社区样本；重量区间使用闭开范围，初始数据覆盖全部重量。
- 不改 20/x 或 22/x 协议形状；客户端基线仍为 4.0.25034。回滚为回退本改动，旧玩家库由新增迁移升级。

## Testing Decisions

- 存储层使用真实 SQLite 验证重量区间优先级、来源记录、商城同店物品覆盖和缺失回退。
- 行为层验证鱼市询价与出售均优先命中表价，且未命中仍使用原有算法。
- 期望值使用手写表价和手算重量结果；移除表查询后这些断言会失败。

## Out of Scope

- 本次不宣称现有社区样本或静态快照已等同官服，也不批量伪造未抓到的逐图/逐店价格。
- 不改变商城商品集合、库存刷新策略、鱼市新鲜度或日价格系数。

## Further Notes

- [事实] 当前鱼市基础表只有阿赫图巴河 251 种四档记录，文件自身标注为 RF4DB 玩家上报与截图校对。
- [事实] 当前静态货架有 52 家逐店记录；商店目录覆盖 205 家店，其余会使用模板或补齐逻辑。
