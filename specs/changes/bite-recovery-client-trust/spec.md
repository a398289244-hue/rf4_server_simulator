# 咬口恢复：客户端确认与入水兜底

Status: implemented

## Problem Statement

多人反馈“没口、脱钩、没鱼”。运行日志显示服务端已下发 27 尾鱼，其中 25 尾由客户端
上报未上钩离场，只有 2 次 `14/11`；这两次又都被服务端按钩入口容量改判为
`BiteQuality=nibble` 并丢弃。玩家看到客户端已经咬钩，点竿后却被告知只是嘬饵。

另有一条独立的“没鱼”缺口：咬钩 timer 到点时若尚未识别到 `14/7` 入水动画位，
旧逻辑只设置 `NeedBite=true` 并退出。若该钓组不上报已知动画位，本竿会永久等待。

## Solution

- 默认关闭 `hook_nibble_veto`。客户端发出 `14/11` 或海钓 `14/9` 后，服务端直接信任
  中钩确认，不再做钩容量事后暗判，也不再随机执行钩型保持失败。
- 保留 `hook_nibble_veto=1` 作为旧模型对照开关；显式开启时保留 14/15 离场通知。
- 旧模型开启时软化超容量保持率：鱼重不超过钩容量时固定保持 1，之后按较缓
  斜率下降，底线从 0.50 提高到 0.65。
- 新增 `bite_inwater_fallback_seconds`，默认 8 秒。抛竿已被接受但未识别到入水位时，
  到点后按已入水继续判鱼；等待期间重新 arm timer，不再永久卡死。后台值最高按 120 秒执行。

## Testing Decisions

- 默认模式下，极小钩配 12kg 鱼也必须得到 `BiteQuality=solid`、`HookHoldP=1`。
- 手工喂入旧存档的 `nibble` pending 鱼，在默认模式下 `14/11` 必须进入 `Hooked`。
- `hook_nibble_veto=1` 时原有 14/15 否决测试继续通过。
- 缺少 `14/7` 入水位且超过兜底时间时，timer 仍应推送 `14/14`。
- 管理后台 `hook_nibble_veto` 只接受 0/1，并可在重启后保留。

## Out of Scope

- 本轮不改鱼种名册、饵料严格筛选和鱼重曲线。
- 本轮不改客户端本地搏鱼物理。
